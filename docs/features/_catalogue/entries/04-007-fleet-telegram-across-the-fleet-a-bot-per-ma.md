| Fleet | **Telegram across the fleet** (`bin/notify/telegram-machines.sh` · `bin/seat/hermes-telegram.sh`) | One bot per machine, so a message says which machine spoke. The registry (`hodd/identity/machines.yaml`, stub shipped at `hodd/identity/machines.yaml.example` and seeded into every fresh home) names each machine's bot id, chat and **vault path** — never a token. The door answers `list · all · me · count · admins · chat · who · relay`: `me` proves which bot a token belongs to, the member actions are the **member door's** answer asked with *that machine's* bot, and `relay` speaks into another machine's chat as this one, prefixing the sender and **carving a Rune** (`event=telegram.relay`). A missing registry is loud, never an empty list; a token that is not at the row's own vault path is refused **in words**, never a silent exit. **The limit is Telegram's:** a bot cannot enumerate ordinary members — it gets the chat, the count, the administrators and one known user at a time ([who is in a Telegram chat](docs/features/telegram-members.md)), and everyone else exists only as an observation ([the Telegram roster](docs/features/telegram-roster.md)). The ear is separate and reported separately: `hermes-telegram.sh status · check · instructions` reads the Hermes gateway's own state, exits 1 when the gateway is up but no platform is attached, and points at the interactive `hermes gateway setup` without ever printing the token | [Telegram across the fleet](docs/features/telegram-across-the-fleet.md) |
