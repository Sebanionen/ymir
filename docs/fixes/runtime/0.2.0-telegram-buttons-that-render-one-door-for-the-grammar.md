## runtime · 0.2.0 · 2026-11-03 — Telegram buttons that render: one door for the grammar

### Why
The bridge drops malformed button wrappers without an error, so a reply full of intended controls arrived as prose. One door now emits the canonical wrapper and checks a draft for every fault, including the legacy colon form.

### Files
- `bin/notify/telegram-buttons.sh`
- `bin/notify/telegram-buttons.mjs`
- `bin/notify/tests/test_telegram_buttons.sh`
- `docs/features/telegram-buttons.md`
### The fault

Every reply of this session ended with buttons that were written as
`<!--telegram_button: 📜 Bearings|Give me my bearings-->` — a shape that *looks* like the grammar and is
ignored completely by the bridge, which parses only `<!-- telegram_button [ … ] -->` (CML/JSON payload) and a
column-zero ```telegram_button fence. The bridge does not complain: an unrecognized wrapper is simply not an
action, so the reply arrives as prose and the reader never learns that controls were meant.

That is a silent failure of exactly the class this house keeps paying for — the same shape as a schedule that
parses into nonsense, or a card that carries a secret: **no error, no output, no clue.**

### What changed

- **`bin/notify/telegram-buttons.sh`** — one door. `emit --button "label|prompt" …` prints the canonical
  wrapper (footer comment by default; `--in-body` writes the fence); `check FILE|-` reads a draft reply and
  reports every wrapper it finds, with line numbers, and every fault.
- **`bin/notify/telegram-buttons.mjs`** — the grammar as code: the CML cell (`{label|prompt|style|disabled}`),
  the nested row, the JSON form, and the rules that make a button useless — an enabled button with no prompt,
  an unknown style, a label past Telegram's 64 characters, nine in a row, more than six in a reply (the house's
  own rule, with `--allow-many` for the deliberate exception).
- **`check` names the specific mistake that caused this**: the legacy colon form, reported as
  *"legacy colon form — the bridge ignores it"*, so the next hand does not have to rediscover it.

### What was proved

`bin/notify/tests/test_telegram_buttons.sh` — **17 assertions, all passing**: emit → check round trips for the
footer and the in-body fence; the legacy colon form refused and named; an indented wrapper refused; an enabled
button with no prompt refused; an unknown style refused; a nine-button row refused with Telegram's limit named;
seven buttons in a reply refused; an unclosed matrix refused; a chunked long list emitted as legal rows and
checked clean; and a reply with no buttons correctly *not* a fault.

### The law it settles

A control that does not render is worse than no control, because it was *meant* to be tappable. So the markup
is generated by one door and validated by the same door's other half, and no hand writes a wrapper again.
